# DotPilot

Портативный центр управления ПК: сеть, звук, профили, доступ — сегодня; CPU / GPU / вентиляторы — дальше.

## Стек

- **Tauri v2** — Rust-бэкенд + WebView2, один портативный `DotPilot.exe` (~8,5 МБ), манифест `requireAdministrator`, значок в трее.
- **React 19 + TypeScript + Vite 7 + Tailwind v4**, графики на Recharts, состояние в Zustand.
- Rust: `sysinfo` (процессы, CPU, RAM, трафик), `winping` (ICMP без raw-сокетов), `reqwest` (Claude API), PowerShell через `-EncodedCommand` для NetAdapter / NetQoS / служб / реестра / PnP-устройств.
- **Claude API** (`claude-opus-5`, adaptive thinking, `fallbacks: "default"`) — страница «Диагностика Claude» отправляет снимок телеметрии и получает план действий.

## Разгон видеокарты

Управление идёт напрямую через `nvapi64.dll`. Библиотека не экспортирует функции по именам — есть единственный экспорт `nvapi_QueryInterface(id)`, поэтому все вызовы резолвятся по числовым идентификаторам, а структуры описаны вручную в `src-tauri/src/nvapi.rs`.

Каждая структура NVAPI несёт поле `version`, куда зашит её собственный размер, и драйвер его сверяет. Неверная раскладка возвращает ошибку, а не портит память — на этом построен перебор версий: пробуем от новой к старой и берём первую, которую драйвер принял. Благодаря этому модуль переживает обновления драйвера.

Запись везде идёт по схеме read-modify-write: структура читается, меняется одно поле, пишется обратно. Так не затираются поля, назначение которых недокументировано.

### Ядро безопасности

`src-tauri/src/ocsafe.rs`. Правила, на которых всё держится:

- **Намерение пишется на диск раньше, чем что-то попадает в железо** (`sync_all`, без кеша ОС). Если приложение или система погибнут до подтверждения, при следующем запуске в журнале останется неподтверждённая запись — это и есть признак сбоя.
- **Границы живут в коде.** Значения проходят `Bounds::clamp`, а сами границы зажимаются абсолютными потолками, которые нельзя превысить ни настройкой, ни правкой журнала, ни ответом нейросети. Ответ модели здесь — недоверенный ввод.
- **Одно изменение за итерацию**: пока настройка не подтверждена, новая не применяется.
- **Три ступени** — 30 с, 5 мин, 30 мин. В «проверенные» настройка попадает только после длинной.
- **Отличаем падение приложения от падения системы** по моменту загрузки ОС; при перезагрузке журнал Windows проверяется на события 41, 1001 и 6008.
- Комбинация, хоть раз приведшая к сбою, попадает в чёрный список и повторно не предлагается.

Разгон через NVAPI волатилен: драйвер держит смещения только до перезагрузки и не пишет их в карту. Поэтому аварийная перезагрузка сама по себе является полным откатом — именно это и позволяет доверить подбор параметров видеокарты автоматике.

### Встроенные тесты

`src-tauri/src/bench.rs` и `src/lib/gputest.ts`. Разгон редко ломается красиво: гораздо чаще он не роняет систему, а начинает тихо возвращать неверные числа, и проверка «поработало полчаса, не упало» такого не замечает.

Поэтому все тесты построены на детерминированных **целочисленных** цепочках — у целых нет законных расхождений в последнем разряде, в отличие от чисел с плавающей точкой, так что любое отличие результата означает ошибку железа.

- **Процессор** — цепочка на всех логических ядрах; эталон снимается один раз и дальше сверяется под нагрузкой.
- **Память** — заполнение цепочкой и проверка при чтении. Ловит нестабильность после включения EXPO, которая портит данные, но почти никогда не роняет систему сразу.
- **Видеокарта** — вычислительный шейдер WebGPU в том же WebView2, который и так входит в приложение: графический стек в портативный exe ради одного теста не тащится. Первый прогон становится эталоном, остальные сверяются с ним побитно, а выборка из эталона дополнительно проверяется тем же алгоритмом на процессоре — это ловит случай, когда карта ошибается стабильно и потому согласована сама с собой.

Ступень считается пройденной, только если сошлись все четыре признака: нет расхождений контрольных сумм, нет восстановлений видеодрайвера в журнале Windows (события 4101, 13, 14), температура не превысила потолок и тест доработал до конца. Последнее проверяется отдельно: зависший тест — это не успех.

### Петля с Claude

`src-tauri/src/ocloop.rs`. Модель получает снимок карты и весь журнал подбора — что проверено, что отклонено и почему — и предлагает **один** следующий шаг.

Ответ забирается через tool-use с обязательной схемой, а не разбором свободного текста: так на выходе всегда структура, а не «почти JSON». Но структурность не равна доверию — предложение проходит `Bounds::clamp`, и выйти за коридор оно не может. Модель здесь советчик; допустимость решает код, и расхождение между тем, что просили, и тем, что применилось, показывается в интерфейсе.

Направление подбора задано целью владельца: не «больше кадров любой ценой», а больше кадров на ватт. Поэтому промпт ведёт от связки «пониженный лимит мощности плюс положительное смещение ядра» — так карта холоднее, тише и живёт дольше, — а не от подъёма лимита до потолка. Память трогается последней: её ошибки самые тихие.

Автоподбор гоняет цикл «спросить шаг → применить → прогнать ступень → вернуть исход модели» и останавливается по кнопке, по решению модели или по ошибке.

## Советник по BIOS

`src-tauri/src/platform.rs`. Реальные рычаги Zen 4 — EXPO, PBO и Curve Optimizer — живут в BIOS, и из Windows их не переключить без кернел-драйвера. Поэтому приложение делает то, что умеет честно: **меряет до и после**. Владелец меняет значение в BIOS, а приложение говорит числами, стало ли лучше.

Замер объединяет встроенные тесты и фактическую частоту под нагрузкой (счётчик `% Processor Performance`, а не `CurrentClockSpeed` — тот часто отдаёт паспортное значение независимо от происходящего). Замеры хранятся, соседние сравниваются автоматически.

Включённость профиля памяти определяется по **напряжению**, а не по частоте: JEDEC для DDR5 — это 1.1 В, любой профиль EXPO или XMP поднимает минимум до 1.25 В. Частота одна ненадёжна, потому что базовые скорости JEDEC растут от поколения к поколению.

Температуры процессора здесь сознательно нет: на Ryzen без кернел-драйвера её не прочитать, а показывать выдуманную величину хуже, чем не показывать никакой.

Claude получает замеры и возвращает через tool-use конкретные пункты BIOS с путями в меню, значениями, обоснованием и способом отката. Применяет их владелец — приложение только подтверждает результат.

## Прокси-страж

Happ в режиме системного прокси слушает 127.0.0.1:10809; Claude Code берёт прокси только из HTTP_PROXY/HTTPS_PROXY, а эти переменные глобальные. DotPilot раз в 5 с проверяет порт: если он мёртв, временно убирает переменные и выключает системный прокси (и возвращает всё, когда Happ снова отвечает), добавляет 26.*/25.* (Radmin) и локальные сети в исключения. «Прямые» приложения (Minecraft, Warface) запускаются из DotPilot с очищенными переменными и `-Djava.net.useSystemProxies=false`, «через Happ» — с переменными только при живом порте.

## Лог для ИИ

Кнопка «Лог для ИИ» на Главной собирает Markdown за всё время работы (история пингов до 2 часов): статистика по целям, инциденты потерь и всплесков с контекстом (CPU, трафик, запущенные приложения, Happ/zapret, топ процессов — записывается каждые 30 с), состояние сети, политики, журнал, плюс инструкция для нейросети в начале. Файл сохраняется и копируется в буфер.

## Энергоэффективность

- Один фоновый поток собирает данные раз в 3 с (CPU, RAM, трафик, процессы через `sysinfo`); PowerShell вызывается только для медленных вещей (службы, адаптеры, QoS) раз в 5–12 с, одним скриптом на уровень.
- Окно свёрнуто в трей → опрос раз в 8 с, PowerShell раз в 20–60 с, интерфейс не обновляется, netsh не вызывается.
- Собственная нагрузка видна на Главной, в «Процессах» и в «Настройках» (тест на 60 с): цель до 1% CPU.
- Ошибки не исчезают сами: их можно развернуть, скопировать, закрыть все по Esc.

## Сбросы

«Сбросить звук» (страница Звук), «По умолчанию» для твиков и «Снять QoS» (Сеть), «Откатить» на странице Доступ, «Сбросить все настройки» (Настройки).

## Трей

Крестик прячет окно в трей. ПКМ по значку: живые строки (пинг, Wi-Fi, Happ/Radmin/zapret, CPU/GPU, запущенные игры) и действия: игровой режим, профиль, zapret, Happ, очистка DNS, применить политики, выход. ЛКМ открывает окно. Горячие клавиши в окне: Ctrl+1…9, Ctrl+0 — страницы.

## Игровой режим

Когда запущено приложение типа «игра» (Warface `Game.exe`, Minecraft `LL.exe`/`javaw.exe`), DotPilot создаёт QoS-политики Windows (`DotPilot-*`):

- играм — `DSCPAction 46` (EF): роутеры с WMM переводят такие пакеты в очередь AC_VO;
- фоновым приложениям (Claude Code / node, Docker) — `ThrottleRateActionBitsPerSecond` по лимиту из настроек и `DSCP 8`.

Когда игра закрывается, лимиты снимаются.

## Сборка

```bash
npm install
npm run tauri build        # → src-tauri/target/release/dotpilot.exe (с манифестом администратора)
DOTPILOT_NO_ADMIN=1 npm run tauri build   # вариант без UAC для отладки
npm run tauri dev          # разработка
```

Конфиг: `DotPilot.config.json` рядом с exe. Удали файл — вернутся значения по умолчанию.
